# 我是怎么建这个库的(给徒弟的版本)

> 这是我把自己跑过一遍的知识库搭建过程,**简化给你看**。你不需要复刻我的结构,你需要用它**理解怎么搭你自己的**。

## 1. 为什么要有个人知识库

> 4 个真实原因:

1. **记忆外挂**:你每天做的事 / 看的项目 / 走的路,如果不写下来就丢了
2. **搜索 + 反向链接**:Obsidian 的双向链接让你能从任何点跳到任何点
3. **跨设备**:本地 + GitHub 同步,出差也能用
4. **AI 时代的工作底座**:你能用 Codex 读它、写它、扩展它

## 2. 三步搭起来

```mermaid
graph LR
  S[开始] --> A[Step 1:装 Obsidian]
  A --> B[Step 2:建本地 vault]
  B --> C[Step 3:Git 同步]
  C --> D[Done]
```

### Step 1:装 Obsidian

- 下载 portable 版本(免安装)
- 放到 `C:\kaifa_boot\Obsidian\`(我用的路径)
- 不需要登录 / 不需要同步服务

### Step 2:建本地 vault

- 选一个文件夹,比如 `C:\my_know`
- 在文件夹里建 `.obsidian/` 子目录
- 创建第一张卡: `README.md`
- 创建 `10_Profile/我是谁.md`、`我在哪.md`、`我要去哪.md`

### Step 3:Git 同步

```bash
cd C:\my_know
git init
git -c core.autocrlf=false add -A
git -c core.autocrlf=false commit -m "init: 知识库第一版"
# 在 GitHub 创建一个空仓库
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

**关键**:`.gitignore` 必须排除:
- `.obsidian/workspace.json`
- `.obsidian/cache/`
- 大文件目录(比如我排除 vibe-hub pages)

## 3. 结构怎么设计

不要直接抄我的结构。**先问自己 3 个问题**:

1. **你是谁** → 哲学三问(我是谁 / 我在哪 / 我要去哪)
2. **你做什么** → 教学 / 项目 / 内容 / 工作 四大类
3. **你怎么用 AI** → Codex / DeepSeek / Claude 等

然后按这 3 类建目录。

## 4. 哲学三问怎么写

不要写"我是程序员 + 会 Python + ..." 这种清单。**写故事**。

```markdown
# 我是谁

## 我的来历
我是哪里人、怎么走到今天。

## 我现在的样子
用一个 Mermaid 图画"我"和我的几个角色。

## 我重视的事
3 件事。

## 我不擅长的事
3 件事。
```

**不要超过 1 页**。每页都要能跳到证据。

## 5. 每张卡都要有证据

我用的方式是** dossier 体系**:

```
20_Projects/<name>.md  ←  项目卡(讲清楚对谁、为什么)
  ↓ 引用
60_Assets/dossiers/<name>.md  ←  真实档案(事实 / 推断 / 待确认)
  ↓ 引用
C:\kaifa\<name>\  ←  真实代码 / 截图 / 数据
```

**不要写"我会 React"**。要写"我做了 senlin_website,用的是 React 18,部署在 codebn.cn,代码在 C:\kaifa\my_website,档案在 [[60_Assets/dossiers/senlin_website]]"。

## 6. 用 Codex 帮你写

不是"我写一段 → 你接一段",而是:

```
Codex:  读 C:\kaifa\my_website\package.json + server.js
        给我真实代码摘要

你:     看摘要 + 加你的判断 + 让 Codex 写 Obsidian 卡
```

**循环几次,质量就上来了**。

## 7. 自动化脚本

```python
# 90_Scripts/audit_dossiers.py · 自动审计你的档案
# 检查项:
#   - frontmatter 必填字段
#   - 正文必含段
#   - 引用了真实文件路径
#   - 含 事实/推断/待确认 三段
```

每个季度跑一次,看 dossier 是不是过时了。

## 8. 我的教训

- **不要全抄**:你跟我的项目不一样,直接抄没用
- **先 dossier 后卡**:不要先写卡片再补证据
- **保持项目干净**:每加一张卡都要想清楚它属于哪个目录
- **可视化很重要**:Mermaid 图比文字更直观
- **季度复盘**:每 3 个月重读一遍"我是谁 / 我要去哪",调整路线

## 9. 你不需要现在就建

如果你的项目还没成型,**不要先建知识库**。先做项目,等有 3-5 个能讲清楚的东西,再建库。

## 10. 我现在用什么

- **Obsidian**:知识库前端
- **Codex**:开发 + 写卡 + 自动化
- **IntelliJ IDEA**:工程入口
- **GitHub**:云端备份
- **Mermaid**:关系图
- **PowerShell**:本地脚本
