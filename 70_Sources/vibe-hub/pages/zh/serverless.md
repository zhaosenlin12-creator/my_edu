# Serverless

你可能会说

我就一个小功能，不想买服务器也不想运维，有没有按次跑代码的？

**把后端代码交给云平台按请求或事件运行，不必自己管理服务器和扩缩容**·例如，用户提交联系表单后，一个 Serverless 函数可以保存内容并发送通知。它并非没有服务器；运行时长、是否保存状态和费用仍受平台规则限制。

### 什么时候用

- 小型网站的 API、表单提交、支付回调和定时任务

  适合短小、事件驱动的任务

  HTTP**提交表单**Webhook**支付回调**Cron**每日汇总**
- 希望跟随前端一起部署，不想先维护 VPS

  前端与函数一起部署

  git push→构建页面 + API→获得网址

  可由平台托管运行环境，仍需管理配置、监控和成本
- 把每个函数设计成短小、无状态、可重复执行

  状态放到外部服务

  请求→短时函数→数据库 / 存储
- 在平台设置中配置 env-var，不要写进仓库

  密钥放平台设置

  环境变量**AI\_API\_KEY = ••••••••**Git 仓库**不包含密钥**

### 什么时候不用

- 不要把长时间转码或永久连接直接放进短时函数

  任务时间超过函数上限

  视频转码**预计 10 分钟**
  *→*
  函数上限**10 秒后超时**
- 依赖函数内存保存状态：后续请求可能由不同实例处理

  下一次请求可能换实例

  实例 A 内存**count = 8**
  *→*
  实例 B 内存**count = 0**

  需要保留的数据应该写入数据库或缓存
- 忽略超时、区域、并发和计费限制

  上线前先看平台限制

  超时**10s**区域**sin1**并发**100**本月调用**82%**
- 把平台绑定写满业务每一层，未来难以迁移

  业务逻辑被平台 API 包住

  vercel.only.doBusinessRule()cloudflare.only.saveOrder()

  平台专用 API 过多会提高迁移或重构核心规则的成本

组成结构 · Anatomy

平台入口→函数实例→外部状态

1平台入口Gateway平台负责网址、HTTPS、扩缩容和请求分发

2函数Function你的代码只在请求或事件到来时执行

3外部状态External State持久数据放数据库或存储服务，不依赖函数内存
