### 构建Build

### 持续集成CI

每次提 PR 都自动跑构建、Lint 和测试，失败就先别合进主分支。

测试11 个条目

### 验收标准Acceptance Criteria

先把这个旅行攻略怎么算完成写清楚：每天有路线、交通时间和官方开放信息，缺一项就不能验收。

### 测试用例Test Case

把登录失败写成一条别人也能照着重现的测试：准备什么、点哪里、最后应该看到什么。

### 单元测试Unit Test

先单独测一下总价计算函数，优惠券、运费和边界值都别连真实支付。

### 集成测试Integration Test

别只测函数，确认下单接口真的能把订单写进测试数据库，再把结果读回来。

### 端到端测试End-to-End Test

像游客本人一样，从选择日期、预订行程一直点到确认页，把整条流程跑一遍。

### 冒烟测试Smoke Test

新版本刚部署，先用几分钟检查首页、登录和预订入口，坏一个就先别继续。

### 回归测试Regression Test

这次只改了优惠券，也要确认原来的支付、退款和订单查询没有被带坏。

### 测试覆盖率Test Coverage

别只报一个覆盖率数字，直接指出支付流程还有哪些高风险分支没有测到。

### 测试替身Test Double

单测别真的扣款，用一个可控的支付替身返回成功和超时，再检查订单模块怎么处理。

### 测试数据与 FixtureTest Data and Fixture

每次测试前都准备同一个用户和订单，跑完后清理掉，保证下一次还是同样的起点。

### 不稳定测试Flaky Test

同一个 commit 的测试一会儿过一会儿不过，别只点重试，查清是时序还是共享数据。
